# About the data in this repository

The dashboard was built against a real HR database. **Nothing identifying from it is in this
repository.** The published dataset is synthetic, generated by replacing values in place
while preserving everything the documentation relies on.

## What was replaced

| Field | Original | Published |
|---|---|---|
| Employee name (10 tables) | real names | generated names, one stable synthetic name per original, consistent across every table |
| Date of birth | full date, 814 records | year preserved, month and day set to 01-01 |
| Mobile number | 369 populated | generated numbers, same 369 records populated |
| Emirates ID number | 130 populated | `EID-######`, same 130 records populated |
| Passport number | 76 populated | `PP-######`, same 76 records populated |
| Visa / labour card / contract number | as recorded | `VIS-` / `LC-` / `AG-######`, same records populated |
| System user codes | real codes | `user001`… |
| Database host and name | real values | `db.example.internal`, `HR_STAGING` |
| School name | real name | `Example School` |

## What was preserved

Employee number, HR status, service status, staff type, gender, nationality, designation,
department, join date, and **all attendance and leave data** — every punch count, days
present, late arrival, arrival time, absence and leave record.

Row counts are identical: 44 tables, 36,448 rows total.

Every figure quoted in the README and the documentation still holds against the published
file:

```
roster names   814      hrms mobile   369      att_emp rows     211
hrms dob       814      hrms eid_no   130      att_day rows  28,416
hrms nat       743      hrms pp_no     76      open_days rows   242
```

## What was removed entirely

`prototype/extracted/dashboard.js` in the original bundled the code **and** the real dataset
in one 3.9 MB file. It is not published. [`dashboard.code-only.js`](prototype/extracted/dashboard.code-only.js)
is the same code with no data, and [`data.json`](prototype/extracted/data.json) is the
synthetic dataset — together they serve the same purpose.

## Verification

After generation the published file was checked for leakage: zero overlap between the 803
original distinct names and the 803 synthetic ones, no original name or document number
present anywhere in the output, the embedded data still parses as valid JSON, line count
unchanged, and the file still makes zero external requests.

Substring coincidences were checked by hand and dismissed: the nationality string
`"British - CAyman Island"` (a typo present in the source) contains a name fragment, and
four junk placeholder values in the original (`1233`, `0000`, `111`, `4`) are short enough
to appear by chance in a 3.7 MB file.

Generation is deterministic under a fixed seed, so the mapping is reproducible but the
synthetic names carry no relationship to the originals.
